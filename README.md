# ШМАВИТО

Публичный каталог предложений Avito для сообщества STEEL. В проекте уже есть адаптивный интерфейс, Twitch OAuth, серверные сессии, PostgreSQL-модель и API первого рабочего контура.

## Локальный запуск

```bash
pnpm install
copy .env.example .env.local
docker compose up -d
pnpm exec prisma migrate deploy
pnpm db:seed
pnpm dev
```

Откройте `http://localhost:3000`.

Для Docker Desktop выполните `docker compose up -d`. Если PostgreSQL уже установлен локально, достаточно указать его адрес в `DATABASE_URL`.

## Twitch OAuth

1. Создайте приложение в Twitch Developer Console.
2. Добавьте redirect URL `http://localhost:3000/api/auth/callback/twitch`.
3. Заполните `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET` и `AUTH_SECRET` в `.env.local`.
4. Первый вход пользователя `rafchibiskus` привяжет основателя к его Twitch ID. Для production лучше заранее указать `FOUNDER_TWITCH_ID`.

Секреты и токены не попадают в клиентский JavaScript. Сессия подписана и хранится в `HttpOnly`, `SameSite=Lax` cookie. Перед production обязательно замените Twitch Secret, `AUTH_SECRET` и `CRON_SECRET` на независимые случайные значения. `TRUST_PROXY_HEADERS=true` допустим только за доверенным reverse proxy, который перезаписывает клиентские forwarding-заголовки.

## Инфраструктура

```bash
docker compose up -d
```

Основная команда поднимает PostgreSQL и Redis. MinIO подключён отдельным необязательным профилем для следующего этапа хранения изображений:

```bash
docker compose --profile storage up -d minio
```

Порты инфраструктуры привязаны только к `127.0.0.1`, поэтому база, Redis и MinIO не публикуются в локальную сеть.

## Реализовано в UI

- приветственный экран STEEL и адаптивный каталог;
- поиск, категории, сортировки, фильтры по городу, непросмотренным и закладкам;
- персональная серверная отметка просмотра и закладки, доступные после входа через Twitch;
- серверные лайки, карточка объявления, комментарии, ответы и жалобы;
- форма предложения с автоматическим импортом названия, цены, города, описания и фотографий Avito, объединением частичных ответов и ручным fallback;
- живой личный кабинет с заявками, статистикой и уведомлениями;
- панель модерации с полным превью объявления, ссылкой на Avito и редактированием данных;
- Prisma-схема, начальная миграция и seed категорий;
- Docker Compose для PostgreSQL, Redis и S3-совместимого MinIO.

## Реализовано в backend

- серверный Twitch Authorization Code Flow и получение профиля Helix;
- подписанная сессия и роли `USER`, `MODERATOR`, `FOUNDER`;
- безопасная привязка основателя и модераторов к Twitch ID;
- публичный API категорий;
- публичный API каталога и серверная отметка просмотра;
- API создания и просмотра собственных заявок с лимитом и защитой от дублей;
- очередь модерации, одобрение/отклонение, обязательная причина отказа;
- публикация карточки и внутреннее уведомление при решении;
- добавление и редактирование категорий;
- редактируемый лимит активных заявок;
- журнал критичных действий.
- серверные лайки, комментарии, ответы и очередь жалоб.
- постоянные лимиты частоты запросов для импорта, заявок, комментариев, лайков, просмотров и жалоб;
- лимит размера JSON, CSP и остальные защитные HTTP-заголовки;
- ежедневная проверка доступности объявлений с журналом результатов и ручным запуском из админки.
- живые показатели опубликованных карточек, очереди, жалоб и ошибок проверки в обзоре админки.
- живые счётчики находок, ожидающих модерации заявок и переходов на Avito на главной странице; значения загружаются на сервере и обновляются при открытой вкладке раз в минуту;

## Ежедневная проверка объявлений

Фоновая задача вызывается POST-запросом с отдельным секретом:

```bash
curl -X POST -H "Authorization: Bearer $CRON_SECRET" https://shmavito.example/api/cron/availability
```

На production этот маршрут нужно вызывать планировщиком один раз в сутки. Проверка консервативна: ограничения и временные ошибки Avito записываются как ошибки и не снимают карточку; серое состояние включается только при подтверждённой недоступности.

Главная страница сразу показывает объявления и статистику из базы. При пустом каталоге карточки не подменяются демонстрационными. Панель модерации получает очередь из базы и требует Twitch-роль модератора или основателя.

Для старых объявлений, в которых остались крошечные миниатюры, можно обновить адреса публичных изображений:

```bash
pnpm images:refresh
```

Импорт предпочитает более крупные изображения публичного предпросмотра Avito. Их реальное разрешение ограничено источником: увеличение в браузере не создаёт недостающие детали. Для оригиналов в полном размере потребуется поддерживаемый источник изображений Avito и последующее хранение копий в S3/MinIO.

Основные маршруты находятся в `app/api`. Все изменяющие запросы проверяют источник, сессию и роль на сервере.

## Проверка

После запуска PostgreSQL и dev-сервера основной серверный контур можно проверить одной командой:

```bash
pnpm test:smoke
```

Тест временно создаёт изолированных пользователей и проверяет каталог, живые счётчики, сессию, просмотры, закладки, переходы на Avito, лайки, комментарии, ответы, уведомления, жалобы и решения модератора. После завершения тестовые записи удаляются.

Чтобы дополнительно проверить автоматическое распознавание на реальной Avito-ссылке в PowerShell:

```powershell
$env:SMOKE_AVITO_IMPORT="1"; pnpm test:smoke; Remove-Item Env:SMOKE_AVITO_IMPORT
```

Конкретную ссылку можно передать через переменную `SMOKE_AVITO_URL`.
Минимальное ожидаемое число фотографий задаётся через `SMOKE_EXPECT_MIN_IMAGES`.
