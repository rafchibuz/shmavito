# ШМАВИТО

Публичный каталог предложений Avito для сообщества STEEL. В проекте уже есть адаптивный интерфейс, Twitch OAuth, серверные сессии, PostgreSQL-модель и API первого рабочего контура.

## Локальный запуск

```bash
pnpm install
copy .env.example .env.local
docker compose up -d
pnpm db:push
pnpm db:seed
pnpm dev
```

Откройте `http://localhost:3000`.

Для Docker Desktop выполните `docker compose up -d`. Если PostgreSQL уже установлен локально, достаточно указать его адрес в `DATABASE_URL`.

## Twitch OAuth

1. Создайте приложение в Twitch Developer Console.
2. Добавьте redirect URL `http://localhost:3000/api/auth/callback/twitch`.
3. Заполните `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET` и `AUTH_SECRET` в `.env.local`.
4. Первый вход пользователя `rafchibiskus` привяжет основателя к его Twitch ID. Для production лучше заранее указать `FOUNDER_TWITCH_ID`.

Секреты и токены не попадают в клиентский JavaScript. Сессия подписана и хранится в `HttpOnly`, `SameSite=Lax` cookie.

## Инфраструктура

```bash
docker compose up -d
```

Команда поднимает PostgreSQL, Redis и MinIO. Сейчас PostgreSQL используется приложением, а Redis и MinIO готовы для следующего этапа фоновых проверок и хранения изображений.

## Реализовано в UI

- приветственный экран STEEL и адаптивный каталог;
- поиск, категории, сортировки и фильтр непросмотренных;
- персональная отметка просмотра в `localStorage`;
- лайки, карточка объявления, комментарии и ответы в демо-режиме;
- форма предложения с валидацией ссылки Avito и имитацией импорта;
- личный кабинет с заявками и уведомлениями;
- рабочий прототип панели модерации;
- Prisma-схема, начальная миграция и seed категорий;
- Docker Compose для PostgreSQL, Redis и S3-совместимого MinIO.

## Реализовано в backend

- серверный Twitch Authorization Code Flow и получение профиля Helix;
- подписанная сессия и роли `USER`, `MODERATOR`, `FOUNDER`;
- безопасная привязка основателя и модераторов к Twitch ID;
- публичный API категорий;
- API создания и просмотра собственных заявок с лимитом и защитой от дублей;
- очередь модерации, одобрение/отклонение, обязательная причина отказа;
- публикация карточки и внутреннее уведомление при решении;
- добавление и редактирование категорий;
- редактируемый лимит активных заявок;
- журнал критичных действий.

Основные маршруты находятся в `app/api`. Все изменяющие запросы проверяют источник, сессию и роль на сервере.

## Следующий этап

Импорт публичных метаданных Avito с ручным fallback, подключение админ-интерфейса к новым API, комментарии/лайки на сервере, файловое хранилище и ежедневная фоновая проверка доступности.

Все карточки и показатели текущей версии являются демонстрационными.
